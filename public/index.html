how an answer is made

  1. Route. Arithmetic goes to an exact calculator. Questions DARLE can prove from memory are answered there, with no model call and no cost.
  2. Recall. Otherwise it pulls what it holds about the things you mention and hands those facts to the model.
  3. Generate. The model must reply in a fixed shape: answer, checkable claims, optional calculation. Anything else is rejected and re-asked.
  4. Calculate. The model asks for arithmetic instead of doing it. The result comes back as a fact.
  5. Verify. Each claim is checked against memory. A conflict sends the model back with the evidence. After four tries DARLE declines instead of guessing.
  6. Learn. Only facts you state are stored. The model's output never is, so a wrong answer cannot contaminate later ones.

limits

  • Reasoning quality is the attached model's. DARLE catches three things: claims that conflict with facts it holds, wrong arithmetic, and malformed output.
  • Claims outside DARLE's relation forms, or about things it holds nothing on, are shown as unverified, not as true.
  • Without a model attached it answers only from memory and the calculator.
  • Memory lives in RAM and is cleared on restart.
